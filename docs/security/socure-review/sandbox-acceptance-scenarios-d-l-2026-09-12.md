## Defect found (DATA INTEGRITY) — PR #134, returned for review, not merged

Six concurrent deliveries of one new event all returned `idempotent_same_result` (one record written, no state change) but none `duplicate_event`: the event marker was checked before the record was written and both writes were blind puts. Against a non-terminal record, two identical concurrent deliveries could both apply. PR #134 takes the webhook decision inside the store's transactional `update` (Firestore `runTransaction`; prototype per-key lock), recording the event id on the record so the second decision writes nothing; assertion: five concurrent deliveries → exactly one `applied`. F–L evidence above was collected on the pre-fix revision; L's concurrency line is to be re-run after #134 deploys.
