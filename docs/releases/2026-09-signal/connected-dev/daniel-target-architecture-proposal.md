# Proposal to Daniel — target identity, KYC, admission and brokerage architecture (2026-09-11)

Founder direction: stop sending broad questions; propose the target architecture and ask only whether the backend supports it or where alpha.3 needs an addendum. Status vocabulary: **CONFIRM** (backend already supports) · **ADDENDUM** (alpha.3 change needed) · **DEFER** (agreed later).

## Target flow

```
Stytch authentication → explicit Alpha invitation (backend cohort membership)
→ profile / disclosures / consents → Socure KYC + Fraud + Watchlist (DocV if required)
→ automatic ReFi Alpha admission (ReFi policy; backend persists the canonical record)
→ Daniel backend opens/links the Alpaca brokerage account (Broker API)
→ Alpaca brokerage approval → account sync → AccountAuthorization → Signal → Managed Paper
```

Three decisions, none substitutes for another: **Socure ACCEPT** = this person satisfies ReFi's KYC and may enter the Alpha · **Alpaca APPROVED/ACTIVE** = this brokerage account is operational · **AccountAuthorization** = this account may use this economic product.

## The two strongest asks

**Cohort:** we want a dedicated positive cohort-membership object rather than deriving invitation membership from onboarding progression. If that cannot land before the Alpha, please explicitly bind the six invited onboarding states as the temporary positive cohort set in the addendum.

**Admission:** ReFi owns the automatic admission policy. We want the backend to persist a separate canonical admission record after ReFi's trusted KYC and onboarding prerequisites pass. Compliance attestation remains evidence, not the admission state. AccountAuthorization remains downstream and separate.

**Direction:** move to Alpaca Broker API account opening rather than per-user Trading API keys as the long-term target.

## What ReFi has already implemented against this (held for your answers)

PR F/G: automatic admission rule `refi.alpha.admission.v1`, atomic admission record, positive cohort allowlist pinned to alpha.3's enum, re-evaluation at every server boundary. Merged: Socure provider foundation, Evaluation API + Digital Intelligence, DocV + authenticated webhook, trusted evidence → attestation (PRs B–E).
