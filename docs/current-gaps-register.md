# Current Gaps Register — Phase 0

**Date:** 2026-05-20
**Scope:** Every confirmed gap between the present state of `refi-us-sec-ia` + `refinity-main-main` and a production-claim of SEC Rule 203A‑2(e) reliance. Each row carries evidence (file path or table name), severity, owner, and a concrete first action.

**Severity:**

- **P0** = blocks IA exemption reliance / blocks beta launch
- **P1** = blocks GA / required for soft launch with friendly users
- **P2** = post-launch hardening

**Owner shorthand:** `FE` = this repo (frontend) — UI under `apps/web/app/us/*`. `BFF` = the still-to-be-built investor BFF in `apps/web/app/api/v1/*` (also frontend-owned). `Counsel` = SEC counsel & compliance. `Zeshan` = product decisions. **`Upstream`** = blocked on Daniel's backend (out of frontend scope; we do not modify `refinity-main-main`).

## Scope correction (2026-05-20)

This repo will **not** modify Daniel's backend. Every gap previously labeled `BE` is reframed using the three-bucket rule from `memory/policy_bff_prototype_state.md`:

- **Bucket A — MSW + dev label:** backend skeletons we mock at the network layer. Investor UX is not blocked. Applies to: **G-002** (auth-siwe), **G-004** (KYC), **G-011** (compliance-adapter).
- **Bucket B — BFF-owned prototype storage:** missing product-state tables that are core to the investor flow and that the 203A‑2(e) test path requires. We persist them ourselves under `apps/web/lib/prototype-store/*`, label projections with `source: "prototype-bff"`, `systemOfRecord: false`, `upstreamGap: "G-XXX"`. Applies to: **G-003** (profile), **G-005** (disclosure registry), **G-006** (lifecycle), **G-007** (auth↔trading link).
- **Bucket C — Upstream-only:** infrastructure rows we do not replicate. Applies to: **G-013** (support persistence — investor surface exists; persistence is upstream), **G-014** (RBAC), **G-103** (FLOAT64), **G-105** (Secret Manager), **G-107**, **G-108** (lifecycle hardening).

Frontend-owned rows (BFF scaffolding, UI surfaces, tripwires, copy, tests) are unchanged in priority — those are where we work.

Not executed in CI yet; webServer needs `SESSION_SECRET`/`ELIGIBILITY_JWT_SECRET` and the config already provides test values. Phase 2 should add a CI lane.
