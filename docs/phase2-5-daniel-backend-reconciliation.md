## 0. Executive summary

**Headline finding.** `live-components-main` is the **ML signal generation + portfolio analysis** backend. It does **not** implement the investor-product API contract that the frontend (`refi-us-sec-ia`), the BFF, or the OpenAPI spec at `packages/api-clients/openapi/refi-api.yaml` assume. The investor product API surface is, today, an entirely **frontend/BFF construct** backed by:

- MSW handlers (`packages/api-clients/src/mocks/handlers.*.ts`) that simulate the API in browser tests.
- The Next.js BFF (`apps/web/app/api/v1/investor/**`) plus a prototype JSON store (`apps/web/.refi-prototype-store-e2e`) for non-MSW paths.

The §A–§D Phase 2.5 replacement coverage proves the **frontend boundary** holds. It does not — and cannot, against this backend — prove that the wire-level investor contract is refused on the server side, because the server side of that contract is not present in `live-components-main`.

This was already flagged as a "known limitation" in `phase2-5-gate-cleanup.md`. This document makes it specific, route-by-route.

**Merge implication.** Reconciliation reveals **no branch-blocking conflicts** against the actual scope of `live-components-main`. The frontend does not collide with Daniel's signal/portfolio code. But the merge-into-`main` decision must be made with the explicit understanding that the §A–§D coverage is a frontend assertion, not a backend contract assertion.

## 4. SEC 203A-2(e) boundary cross-check

The Phase 2 + Phase 2.5 boundary claims that must not be weakened by any reconciliation step:

1. **Investor UI never renders a per-trade Accept / Approve / Submit / investor-accept / staff-approval / founder-review affordance.** — Enforced by tripwire + §A + §B + §D. Daniel's backend does not change this; it has no investor-facing surface.
2. **Managed mode is governed by `ExecutionPolicy` activation + pause/resume + Exception Review.** — Defined frontend-side; no Daniel counterpart.
3. **Signal mode is advisory-only.** — Defined frontend-side; no Daniel counterpart.
4. **Support is non-advisory; SBR-\* classifier refuses buy/sell/approve/portfolio-change/model-override prompts.** — Enforced by §D; entirely client-side (the support classifier is `apps/web/app/us/_lib/support-boundary/`). Daniel's backend has no support endpoint.
5. **`InvestorActionReceipt` ≠ `RecordAccessLog`.** — Frontend contract (`memory/contract_receipt_vs_access_log.md`); no Daniel counterpart.
6. **Exception resolution UI labels (`resolve_exception`, `dismiss_exception`) → backend labels (`approve_exception`, `reject_exception`).** — Surface 7 aliasing; no Daniel counterpart.

**None of the boundary claims are at risk from Daniel's backend, because Daniel's backend does not implement any of the surfaces those claims constrain.**
