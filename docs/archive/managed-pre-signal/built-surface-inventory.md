## 3. Architectural mismatches vs Daniel's target (why wholesale merge-back is prohibited)

Measured facts at `42e9603`, mapped to the September governing documents:

1. **~25 browser-direct `apiFetch` endpoints** (`/orders`, `/v1/brokers/*`, `/auth/*`, `/ccid/*`, `/siwe/*`, `/v1/documents/acknowledge`, …) bypass the BFF — the target architecture exposes a private Investor API behind the BFF, never Admin-Portal-era browser-direct calls (exec overview §7.5).
2. **No AccountRecommendation → Managed promotion → AccountIntent chain.** The archived product treats a single-symbol `RecommendationProjection` (including an `executing` status) as the advisory object; Daniel's architecture makes recommendations immutable account-level objects with child legs, promoted to a distinct executable `AccountIntent` only in Managed (§7.4, §8.1).
3. **No separated runtime identities / broker authority model** — Signal vs Managed promoter as separately authorized runtimes, broker credentials isolated to the runtimes that need them (§2.3, §8).
4. **SIWE login hooks still live** while identity is `identity-ccid`, email-first.
5. **Legacy prototype contracts** (`/v1/*` MSW-era shapes) are not the exported Investor API contract (`v1.0.0-dev.1`, pending).
6. The **release gate defect** (asserted, never enforced) and **BFF-412-ENVELOPE** as above.
