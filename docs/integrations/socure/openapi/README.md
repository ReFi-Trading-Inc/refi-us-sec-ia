# Socure RiskOS™ public OpenAPI specifications — derived facts (read-only)

Source: `https://github.com/socure-inc/.github/tree/main/openapi-spec` (public): `riskos-api-spec.json` (Socure RiskOS™ API 2025-01-01.orion) and `riskos-webhooks-spec.json` (RiskOS™ Webhooks 1.0.0), read 2026-09-10. The raw files are NOT vendored (300 KB of vendor examples that trip secret scanners); re-fetch from the source when re-deriving `apps/web/src/lib/kyc/socure/schemas.ts`.

Facts taken from these specs and the public help center (2026-09-10):

- Evaluation: `POST /api/evaluation`, `Authorization: Bearer <API key>` (separate sandbox/production keys). Servers: `https://riskos.socure.com` (production), `https://riskos.sandbox.socure.com` (sandbox).
- Request top level: `workflow` (required), `id` (required, customer-defined, unique per evaluation), `timestamp` (required, RFC 3339), optional `customer_metadata`, `data.individual` (given_name/family_name ≤240, national_id, date_of_birth YYYY-MM-DD, email, phone_number E.164, address{line_1,line_2,locality,minor/major_admin_division,country ISO-3166-1-alpha-2,postal_code}, `di_session_token`, `additional_context.user_consent` (must be true) + `consent_timestamp`, optional `docv.config`).
- Response (200 immediate / 201 paused): `id`, `eval_id` (uuid), `workflow`, `eval_status`, `decision` ∈ ACCEPT|REVIEW|REJECT, `status` ∈ OPEN|ON_HOLD|CLOSED, `sub_status`, `score`, `tags`, `decision_tags`, `reason_codes`, `review_queues`, `data_enrichments[]` (`response` is an open object; the guide places `docvTransactionToken` under `response.data`), `environment_name` ∈ Sandbox|Production.
- Errors: `{ error, code, message, details, invalid_args[] }` with `code` ∈ AUTHENTICATION_FAILED, PERMISSION_DENIED, WORKFLOW_NOT_FOUND, WORKFLOW_NOT_PUBLISHED, INVALID_REQUEST, INVALID_PAYLOAD, INVALID_ID, INVALID_FRAUD_TYPE, INTERNAL_ERROR, CUSTOMER_METADATA_TOO_LARGE; statuses 400/401/403 (IP rejected)/404/413/429/500.
- `GET /api/evaluation/{eval_id}` retrieves an evaluation (reconciliation path if a webhook is lost).
- Webhooks: envelope `event_id` (uuid, idempotency key), `event_at`, `event_type`, `data`; `evaluation_completed.data` carries `id` (our customer reference), `eval_id`, `decision`, `evaluation_status`, `status`, `sub_status`, `score`, `tags`, `reason_codes`, `environment_name`; `evaluation_paused.data.eval_status = evaluation_paused`; `workflow_execution_failed` exists.
- Webhook authenticity (help center "Webhook configuration reference"): **no HMAC signature**. Endpoint auth is configured in the RiskOS dashboard as Basic, Bearer (UUID token) or OAuth 2.0 client credentials, sent on every delivery; plus a documented sender IP allowlist (sandbox `35.230.191.253/32`, `3.218.138.162/32`, `13.217.134.98/32`, `54.85.52.249/32`; production `35.199.32.202/32`, `3.138.161.243`, `54.209.34.129/32`, `100.24.247.109/32`, `44.195.229.53/32`). Retries: ≤10 attempts, exponential to 60 s, on 504/503/502/429/423/409/408; respond 2xx within 30 s.
