### Terraform ↔ `env.ts` reconciliation (PR #156 `main.tf`)

The connected-deployment invariant set for `REFI_INVESTOR_API_CREDENTIAL_MODE=native-cloud-run`
is satisfied exactly: client mode, mint, KMS signing with no ephemeral key, no
mock KYC or controls, live data adapter, non-demo tier, durable store with a
compliant namespace, distinct identity-ccid / investor-api audiences, separate
bridge key + kid + issuer. Four gaps:

1. `IDENTITY_RESULT_ISSUER` / `IDENTITY_RESULT_AUDIENCE` absent → schema defaults.
   For a value deciding whether a backend token is accepted, an unset default is
   a latent mis-binding. Set explicitly once Daniel confirms.
2. `REFI_INVESTOR_API_ALLOW_REMOTE="0"` with non-loopback `*.run.app` hosts:
   the JWKS resolver and gateway refuse, and the chain fails closed. Correct and
   intended, but the deployed service cannot complete one exchange today. A
   deploy is not a certification.
3. No `STYTCH_*` env or secret; `REFI_AUTH_PROVIDER=unconfigured`. The login
   half is unreachable on this service.
4. `connection.dev.json` expects the frontend JWKS at `bff-dev.refi.trading`
   while `main.tf` uses the `run.app` origin for issuer and JWKS. The domain
   mapping is pending; bind once, after deciding which origin.
